自定义扫描提供者通常会通过设置下面的钩子，==为基本关系添加路径==。==核心代码为该关系生成完所有能够生成的访问路径之后，会调用这个钩子==。但 `Gather` 和 `Gather Merge` 路径除外：它们在此次调用之后生成，因此可以使用这个钩子添加的部分路径。

```
typedef void (*set_rel_pathlist_hook_type) (PlannerInfo *root,
                                            RelOptInfo *rel,
                                            Index rti,
                                            RangeTblEntry *rte);
extern PGDLLIMPORT set_rel_pathlist_hook_type set_rel_pathlist_hook;
```

尽管这个钩子函数可以用来检查、修改或删除核心系统生成的路径，但自定义扫描提供者通常只负责生成 `CustomPath` 对象，并通过 `add_path` 将其添加到 `rel`；如果它们是部分路径，则使用 `add_partial_path`。自定义扫描提供者负责初始化 `CustomPath` 对象，其声明如下：

```
typedef struct CustomPath
{
    Path      path;
    uint32    flags;
    List     *custom_paths;
    List     *custom_restrictinfo;
    List     *custom_private;
    const CustomPathMethods *methods;
} CustomPath;
```

`path` 必须像其他任何路径一样进行初始化，其中包括该路径提供的行数估计、启动成本与总成本，以及排序顺序。`flags` 是一个位掩码，用来说明扫描提供者能否支持某些可选能力。如果自定义路径支持向后扫描，`flags` 应包含 `CUSTOMPATH_SUPPORT_BACKWARD_SCAN`；如果支持标记与恢复，应包含 `CUSTOMPATH_SUPPORT_MARK_RESTORE`；如果能够执行投影，应包含 `CUSTOMPATH_SUPPORT_PROJECTION`。（如果没有设置 `CUSTOMPATH_SUPPORT_PROJECTION`，扫描节点只会被要求生成被扫描关系的 `Var`；如果设置了该标志，扫描节点就必须能够对这些 `Var` 上的标量表达式求值。）可选成员 `custom_paths` 是该自定义路径节点所使用的 `Path` 节点列表；规划器会把这些节点转换为 `Plan` 节点。如下所述，也可以为连接关系创建自定义路径。在这种情况下，应使用 `custom_restrictinfo` 保存要应用于该自定义路径所替代连接的一组连接子句。否则，该成员应为 `NIL`。`custom_private` 可用来保存自定义路径的私有数据。私有数据应以 `nodeToString` 能够处理的形式保存，这样，尝试输出该自定义路径的调试例程才能按预期工作。`methods` 必须指向一个实现了所需自定义路径方法的对象，该对象通常采用静态分配；下面将进一步说明这些方法。

自定义扫描提供者也可以提供连接路径。与基本关系一样，这种路径必须产生与它所替代连接通常会产生的输出相同的输出。为此，连接提供者应设置下面的钩子，然后在钩子函数中为连接关系创建一个或多个 `CustomPath` 路径。

```
typedef void (*set_join_pathlist_hook_type) (PlannerInfo *root,
                                             RelOptInfo *joinrel,
                                             RelOptInfo *outerrel,
                                             RelOptInfo *innerrel,
                                             JoinType jointype,
                                             JoinPathExtraData *extra);
extern PGDLLIMPORT set_join_pathlist_hook_type set_join_pathlist_hook;
```

对于同一个连接关系，这个钩子会以不同的内关系与外关系组合被重复调用；钩子负责尽量减少重复工作。

还要注意，要应用于连接的一组连接子句通过 `extra->restrictlist` 传入，并且会随内关系与外关系的组合而变化。为 `joinrel` 生成的 `CustomPath` 路径必须包含它所使用的一组连接子句。如果规划器把该路径选为 `joinrel` 的最优路径，规划器会使用这些子句把 `CustomPath` 路径转换为计划。

### 59.1.1. 自定义扫描路径回调

```
Plan *(*PlanCustomPath) (PlannerInfo *root,
                         RelOptInfo *rel,
                         CustomPath *best_path,
                         List *tlist,
                         List *clauses,
                         List *custom_plans);
```

把自定义路径转换为完整的计划。返回值通常是一个 `CustomScan` 对象，回调函数必须分配并初始化该对象。更多细节请参阅[第 59.2 节](https://www.postgresql.org/docs/17/custom-scan-plan.html "59.2. 创建自定义扫描计划")。

```
List *(*ReparameterizeCustomPathByChild) (PlannerInfo *root,
                                          List *custom_private,
                                          RelOptInfo *child_rel);
```

当把一个以给定子关系 `child_rel` 的最上层父关系为参数的路径，转换为以该子关系为参数的路径时，会调用这个回调。该回调用来重新参数化 `CustomPath` 的给定 `custom_private` 成员中保存的所有路径，或者转换其中保存的所有表达式节点。该回调可以按需使用 `reparameterize_path_by_child`、`adjust_appendrel_attrs` 或 `adjust_appendrel_attrs_multilevel`。
