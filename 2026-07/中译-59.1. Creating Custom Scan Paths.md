自定义扫描提供程序通常会通过设置以下钩子（hook），==为基本关系添加路径==。==在核心代码为该关系生成它所能生成的所有访问路径之后==，系统会调用这个 hook（Gather 和 Gather Merge 路径除外；它们在此次调用之后生成，以便使用该 hook 添加的部分路径）：

```
typedef void (*set_rel_pathlist_hook_type) (PlannerInfo *root,
                                            RelOptInfo *rel,
                                            Index rti,
                                            RangeTblEntry *rte);
extern PGDLLIMPORT set_rel_pathlist_hook_type set_rel_pathlist_hook;
```

尽管这个 hook 函数可以用来检查、修改或删除核心系统生成的路径，==但自定义扫描提供程序通常只生成 `CustomPath` 对象==，并使用 `add_path` 将它们添加到 `rel`；如果它们是部分路径，则使用 `add_partial_path`。自定义扫描提供程序负责初始化 `CustomPath` 对象，其声明如下：

```
typedef struct CustomPath
{
    Path      path;
    uint32    flags;
    List     *custom_paths;
    List     *custom_restrictinfo;
    List     *custom_private;
    const CustomPathMethods *methods;
} CustomPath;
```

- `path` ==必须像其他任何路径一样初始化，包括该路径提供的行数估算、启动成本与总成本，以及排序顺序。==
- ==`flags` 是一个位掩码，用于指定扫描提供程序是否支持某些可选能力==。
	- 如果自定义路径支持向后扫描，`flags` 应包含 `CUSTOMPATH_SUPPORT_BACKWARD_SCAN`；如果支持标记与恢复，应包含 `CUSTOMPATH_SUPPORT_MARK_RESTORE`；
	- 如果能够执行投影，应包含 `CUSTOMPATH_SUPPORT_PROJECTION`。（如果未设置 `CUSTOMPATH_SUPPORT_PROJECTION`，扫描节点只会被要求生成被扫描关系的 Vars；如果设置了该标志，扫描节点就必须能够对这些 Vars 计算标量表达式。）
- 可选的 `custom_paths` 是此自定义路径节点所使用的 `Path` 节点列表；规划器会把这些节点转换为 `Plan` 节点。
- 如下文所述，也可以为JOIN关系创建自定义路径。在这种情况下，==应该使用 `custom_restrictinfo` 保存要应用于自定义路径所替代联接的联接子句集合==。否则，它应为 NIL。
- `custom_private` 可用于保存自定义路径的私有数据。私有数据应以 `nodeToString` 能够处理的形式保存，这样，尝试打印自定义路径的调试例程才能按设计正常工作。`methods` 必须指向一个实现了所需自定义路径方法的对象；该对象通常以静态方式分配，下文将进一步详述这些方法。

==自定义扫描提供程序也可以提供联接路径==。与基本关系一样，这类路径必须生成与它所替代的联接通常会生成的相同输出。为此，联接提供程序应设置以下 hook，然后在 hook 函数内为联接关系创建一个或多个 `CustomPath` 路径。

```
typedef void (*set_join_pathlist_hook_type) (PlannerInfo *root,
                                             RelOptInfo *joinrel,
                                             RelOptInfo *outerrel,
                                             RelOptInfo *innerrel,
                                             JoinType jointype,
                                             JoinPathExtraData *extra);
extern PGDLLIMPORT set_join_pathlist_hook_type set_join_pathlist_hook;
```

对于同一个联接关系，==系统会使用不同的内关系与外关系组合反复调用这个== hook；hook 负责尽量减少重复工作。

==还要注意，要应用于联接的联接子句集合通过 `extra->restrictlist` 传入，它会随内关系与外关系的组合而变化。为 `joinrel` 生成的 `CustomPath` 路径必须包含其使用的联接子句集合；如果规划器将该路径选为 `joinrel` 的最佳路径，规划器就会使用这组子句把 `CustomPath` 路径转换为计划。==

### 59.1.1. ==自定义扫描路径回调==

```
Plan *(*PlanCustomPath) (PlannerInfo *root,
                         RelOptInfo *rel,
                         CustomPath *best_path,
                         List *tlist,
                         List *clauses,
                         List *custom_plans);
```

将自定义路径转换为最终计划。返回值通常是一个 `CustomScan` 对象，回调函数必须分配并初始化该对象。更多细节请参见[第 59.2 节](https://www.postgresql.org/docs/17/custom-scan-plan.html "59.2. 创建自定义扫描计划")。

```
List *(*ReparameterizeCustomPathByChild) (PlannerInfo *root,
                                          List *custom_private,
                                          RelOptInfo *child_rel);
```

当规划器把一个按给定子关系 `child_rel` 的最顶层父关系参数化的路径，转换为按该子关系参数化时，会调用这个回调。该回调用于重新参数化 `CustomPath` 的指定 `custom_private` 成员中保存的所有路径，或转换其中保存的所有表达式节点。回调可以根据需要使用 `reparameterize_path_by_child`、`adjust_appendrel_attrs` 或 `adjust_appendrel_attrs_multilevel`。
