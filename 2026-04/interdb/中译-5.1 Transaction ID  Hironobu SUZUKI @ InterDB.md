# 5.1 Transaction ID

在每个事务开始时，事务管理器会分配一个唯一的标识符，称为 transaction ID（txid）。PostgreSQL 的 txid 是一个 32 位无符号整数，其最大值约为 42 亿（4.2 billion）。

在事务开始后执行内建的 `txid_current()` 函数可以返回当前的 txid，如下所示：

```sql
testdb=# BEGIN;
BEGIN
testdb=# SELECT txid_current();
 txid_current
--------------
          100
row
```

PostgreSQL 保留了以下三个特殊的 txid：

- **0** 表示 **Invalid** txid。
- **1** 表示 **Bootstrap** txid，它只在数据库集群的初始化时使用。
- **2** 表示 **Frozen** txid，这个在后文会描述。

txid 之间可以进行比较。例如，从 txid 100 的视角来看，大于 100 的 txid 属于 "*未来*"，对 txid 100 来说是 *不可见的*；小于 100 的 txid 属于 "*过去*"，是 *可见的*（图 5.1 a）。

![](https://www.interdb.jp/pg/pgsql05/fig-5-01.png)

图 5.1. PostgreSQL 中的 Transaction ids。

由于在实际系统中 txid 空间是不够用的，PostgreSQL 将 txid 空间视为一个圆环。之前的 21 亿个 txid 属于 "过去"，之后的 21 亿个 txid 属于 "未来"（图 5.1 b）。

Info

请注意，BEGIN 命令本身并不会被分配一个 txid。

在 PostgreSQL 中，当 BEGIN 命令执行后的第一个命令被执行时，事务管理器才会分配一个 txid，然后事务才真正开始。
