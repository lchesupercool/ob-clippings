# 3.5.2. Merge Join

与 nested loop join 不同，merge join 只能用于 natural join 和 `equi-joins`。

merge join 的 cost 由 initial\_cost\_mergejoin() 和 final\_cost\_mergejoin() 函数估算。

精确的 cost 估算较为复杂，这里予以省略。我们只讨论 merge join 算法的运行时复杂度。merge join 的 start-up cost 是 inner 表和 outer 表排序 cost 之和。也就是说，start-up cost 为 O(Nouterlog2(Nouter)+Ninnerlog2(Ninner))O(Nouterlog2(Nouter)+Ninnerlog2(Ninner)) $O(N_{outer} \log_2(N_{outer}) + N_{inner} \log_2(N_{inner}))$，其中 NouterNouter $N_{outer}$ 和 NinnerNinner $N_{inner}$ 分别是 outer 表和 inner 表的 tuple 数量。run cost 为 O(Nouter+Ninner)O(Nouter+Ninner) $O(N_{outer} + N_{inner})$。

与 nested loop join 类似，PostgreSQL 中的 merge join 也有四种变体。

## 3.5.2.1. Merge Join

图 3.23 展示了 merge join 的概念图示。

![](https://www.interdb.jp/pg/pgsql03/05/fig-3-23.png)

图 3.23. Merge join。

如果所有 tuple 都能放入内存，则 sort 操作可以在内存中完成。否则将使用临时文件。

下面展示 merge join 的 EXPLAIN 命令结果的一个具体示例。

```sql
testdb=# EXPLAIN SELECT * FROM tbl_a AS a, tbl_b AS b WHERE a.id = b.id AND b.id < 1000;
                               QUERY PLAN
-------------------------------------------------------------------------
 Merge Join  (cost=944.71..984.71 rows=1000 width=16)
   Merge Cond: (a.id = b.id)
   ->  Sort  (cost=809.39..834.39 rows=10000 width=8)
         Sort Key: a.id
         ->  Seq Scan on tbl_a a  (cost=0.00..145.00 rows=10000 width=8)
   ->  Sort  (cost=135.33..137.83 rows=1000 width=8)
         Sort Key: b.id
         ->  Seq Scan on tbl_b b  (cost=0.00..85.50 rows=1000 width=8)
               Filter: (id < 1000)
rows
```
- **第 9 行**：executor 通过 sequential scanning（第 11 行）对 inner 表 tbl\_b 进行排序。
- **第 6 行**：executor 通过 sequential scanning（第 8 行）对 outer 表 tbl\_a 进行排序。
- **第 4 行**：executor 执行 merge join 操作；outer 表是排序后的 tbl\_a，inner 表是排序后的 tbl\_b。

## 3.5.2.2. Materialized Merge Join

与 nested loop join 相同，merge join 也支持 materialized merge join，通过物化 inner 表来提高 inner 表扫描的效率。

![](https://www.interdb.jp/pg/pgsql03/05/fig-3-24.png)

图 3.24. Materialized merge join。

下面展示 materialized merge join 结果的一个示例。可以很容易看出它与上面 merge join 结果的区别在于第 9 行的 'Materialize'。

```sql
testdb=# EXPLAIN SELECT * FROM tbl_a AS a, tbl_b AS b WHERE a.id = b.id;
                                    QUERY PLAN
-----------------------------------------------------------------------------------
 Merge Join  (cost=10466.08..10578.58 rows=5000 width=2064)
   Merge Cond: (a.id = b.id)
   ->  Sort  (cost=6708.39..6733.39 rows=10000 width=1032)
         Sort Key: a.id
         ->  Seq Scan on tbl_a a  (cost=0.00..1529.00 rows=10000 width=1032)
   ->  Materialize  (cost=3757.69..3782.69 rows=5000 width=1032)
         ->  Sort  (cost=3757.69..3770.19 rows=5000 width=1032)
               Sort Key: b.id
               ->  Seq Scan on tbl_b b  (cost=0.00..1193.00 rows=5000 width=1032)
rows
```
- **第 10 行**：executor 通过 sequential scanning（第 12 行）对 inner 表 tbl\_b 进行排序。
- **第 9 行**：executor 对排序后的 tbl\_b 结果进行物化。
- **第 6 行**：executor 通过 sequential scanning（第 8 行）对 outer 表 tbl\_a 进行排序。
- **第 4 行**：executor 执行 merge join 操作；outer 表是排序后的 tbl\_a，inner 表是物化后的排序 tbl\_b。

## 3.5.2.3. Other Variations

与 nested loop join 类似，PostgreSQL 中的 merge join 也有一些变体，依据 outer 表是否可以通过 index scanning 进行扫描来区分。

![](https://www.interdb.jp/pg/pgsql03/05/fig-3-25.png)

图 3.25. 带 outer index scan 的 merge join 的三种变体。

下面展示这些 join 的 EXPLAIN 结果：

(a) 带 outer index scan 的 Merge join

```sql
testdb=# SET enable_hashjoin TO off;
SET
testdb=# SET enable_nestloop TO off;
SET
testdb=# EXPLAIN SELECT * FROM tbl_c AS c, tbl_b AS b WHERE c.id = b.id AND b.id < 1000;
                                      QUERY PLAN
--------------------------------------------------------------------------------------
 Merge Join  (cost=135.61..322.11 rows=1000 width=16)
   Merge Cond: (c.id = b.id)
   ->  Index Scan using tbl_c_pkey on tbl_c c  (cost=0.29..318.29 rows=10000 width=8)
   ->  Sort  (cost=135.33..137.83 rows=1000 width=8)
         Sort Key: b.id
         ->  Seq Scan on tbl_b b  (cost=0.00..85.50 rows=1000 width=8)
               Filter: (id < 1000)
rows
```

(b) 带 outer index scan 的 Materialized merge join

```sql
testdb=# SET enable_hashjoin TO off;
SET
testdb=# SET enable_nestloop TO off;
SET
testdb=# EXPLAIN SELECT * FROM tbl_c AS c, tbl_b AS b WHERE c.id = b.id AND b.id < 4500;
                                      QUERY PLAN
--------------------------------------------------------------------------------------
 Merge Join  (cost=421.84..672.09 rows=4500 width=16)
   Merge Cond: (c.id = b.id)
   ->  Index Scan using tbl_c_pkey on tbl_c c  (cost=0.29..318.29 rows=10000 width=8)
   ->  Materialize  (cost=421.55..444.05 rows=4500 width=8)
         ->  Sort  (cost=421.55..432.80 rows=4500 width=8)
               Sort Key: b.id
               ->  Seq Scan on tbl_b b  (cost=0.00..85.50 rows=4500 width=8)
                     Filter: (id < 4500)
rows
```

(c) 带 outer index scan 的 Indexed merge join

```sql
testdb=# SET enable_hashjoin TO off;
SET
testdb=# SET enable_nestloop TO off;
SET
testdb=# EXPLAIN SELECT * FROM tbl_c AS c, tbl_d AS d WHERE c.id = d.id AND d.id < 1000;
                                      QUERY PLAN
--------------------------------------------------------------------------------------
 Merge Join  (cost=0.57..226.07 rows=1000 width=16)
   Merge Cond: (c.id = d.id)
   ->  Index Scan using tbl_c_pkey on tbl_c c  (cost=0.29..318.29 rows=10000 width=8)
   ->  Index Scan using tbl_d_pkey on tbl_d d  (cost=0.28..41.78 rows=1000 width=8)
         Index Cond: (id < 1000)
rows
```
