# 5.3. 插入、删除与更新 tuple

本节介绍 tuple 是如何被插入、删除和更新的。然后简要介绍用于插入和更新 tuple 的 **Free Space Map (FSM)**。

为了聚焦于 tuple 本身，下文中不再展示 page header 和 line pointer。图 5.3 展示了 tuple 的一个表示示例。

![](https://www.interdb.jp/pg/pgsql05/fig-5-03.png)

图 5.3. tuple 的表示。

## 5.3.1. 插入

在插入操作中，新 tuple 会被直接插入到目标表的某个 page 中（图 5.4）。

![](https://www.interdb.jp/pg/pgsql05/fig-5-04.png)

图 5.4. tuple 的插入。

假设某个 tuple 由 txid 为 99 的事务插入到某个 page 中。在这种情况下，被插入 tuple 的 header 字段将按如下方式设置。

- Tuple\_1:
	- **t\_xmin** 被设置为 99，因为该 tuple 由 txid 99 插入。
		- **t\_xmax** 被设置为 0，因为该 tuple 尚未被删除或更新。
		- **t\_cid** 被设置为 0，因为该 tuple 是 txid 99 插入的第一个 tuple。
		- **t\_ctid** 被设置为 (0,1)，指向它自己，因为这是最新的 tuple。

PostgreSQL 提供了 '==pageinspect==' 扩展（一个贡献模块），用于展示数据库 page 的内容。

```sql
testdb=# CREATE EXTENSION pageinspect;
CREATE EXTENSION
testdb=# CREATE TABLE tbl (data text);
CREATE TABLE
testdb=# INSERT INTO tbl VALUES('A');
INSERT 0 1
testdb=# SELECT lp as tuple, t_xmin, t_xmax, t_field3 as t_cid, t_ctid
                FROM heap_page_items(get_raw_page('tbl', 0));
 tuple | t_xmin | t_xmax | t_cid | t_ctid
-------+--------+--------+-------+--------
     1 |     99 |      0 |     0 | (0,1)
row
```

## 5.3.2. 删除

在 delete 操作中，目标 tuple 被逻辑删除。执行 DELETE 命令的 txid 值会被设置到该 tuple 的 t\_xmax 中（图 5.5）。

![](https://www.interdb.jp/pg/pgsql05/fig-5-05.png)

图 5.5. tuple 的删除。

假设 tuple Tuple\_1 被 txid 111 删除。在这种情况下，Tuple\_1 的 header 字段将按如下方式设置：

- Tuple\_1:
	- **t\_xmax** 被设置为 111。

如果 txid 111 被提交，Tuple\_1 便不再被需要。通常来说，在 PostgreSQL 中不再需要的 tuple 被称为 **dead tuple**。

Dead tuple 最终应从 page 中被清除。清理 dead tuple 的过程被称为 **VACUUM** 处理，相关内容将在 `Chapter 6` 中介绍。

## 5.3.3. 更新

在 update 操作中，PostgreSQL 会逻辑删除最新的 tuple，并插入一个新的 tuple（图 5.6）。

![](https://www.interdb.jp/pg/pgsql05/fig-5-06.png)

图 5.6. 对同一行更新两次。

假设由 txid 99 插入的那一行，被 txid 100 更新了两次。

执行第一次 UPDATE 命令时，Tuple\_1 会被逻辑删除，具体做法是将 t\_xmax 设置为 txid 100，随后 Tuple\_2 被插入。接着，Tuple\_1 的 *t\_ctid* 会被改写为指向 Tuple\_2。Tuple\_1 和 Tuple\_2 的 header 字段如下：

- Tuple\_1:
	- **t\_xmax** 被设置为 100。
		- **t\_ctid** 从 (0, 1) 改写为 (0, 2)。
- Tuple\_2:
	- **t\_xmin** 被设置为 100。
		- **t\_xmax** 被设置为 0。
		- **t\_cid** 被设置为 0。
		- **t\_ctid** 被设置为 (0,2)。

执行第二次 UPDATE 命令时，与第一次 UPDATE 命令一样，Tuple\_2 被逻辑删除，Tuple\_3 被插入。Tuple\_2 和 Tuple\_3 的 header 字段如下：

- Tuple\_2:
	- **t\_xmax** 被设置为 100。
		- **t\_ctid** 从 (0, 2) 改写为 (0, 3)。
- Tuple\_3:
	- **t\_xmin** 被设置为 100。
		- **t\_xmax** 被设置为 0。
		- **t\_cid** 被设置为 1。
		- **t\_ctid** 被设置为 (0,3)。

与 delete 操作类似，如果 txid 100 被提交，Tuple\_1 和 Tuple\_2 将成为 dead tuple；如果 txid 100 被中止，Tuple\_2 和 Tuple\_3 将成为 dead tuple。

## 5.3.4. Free Space Map

当插入一个 heap tuple 或 index tuple 时，PostgreSQL 会使用对应表或索引的 **Free Space Map (FSM)** 来选择可以进行插入的 page。

正如在 `Section 1.2.3` 中所提到的，所有的表和索引都有各自对应的 FSM。每个 FSM 存储着对应表或索引文件中每个 page 的空闲空间容量信息。

所有 FSM 以 'fsm' 为后缀进行存储，必要时会被加载到共享内存中。

扩展 `pg_freespacemap` 提供了指定表/索引的空闲空间。以下查询展示了指定表中每个 page 的空闲空间比例。

```sql
testdb=# CREATE EXTENSION pg_freespacemap;
CREATE EXTENSION

testdb=# SELECT *, round(100 * avail/8192 ,2) as "freespace ratio"
                FROM pg_freespace('accounts');
 blkno | avail | freespace ratio
-------+-------+-----------------
     0 |  7904 |           96.00
     1 |  7520 |           91.00
     2 |  7136 |           87.00
     3 |  7136 |           87.00
     4 |  7136 |           87.00
     5 |  7136 |           87.00
....
```
