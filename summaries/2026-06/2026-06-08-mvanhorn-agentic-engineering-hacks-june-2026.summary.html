Every Agentic Engineering Hack I Know (June 2026) — 摘要

一句话结论

作者把自己整套"代理式工程"(Agentic Engineering)工作流摊开：核心不是自己写代码，而是凡事先让 agent 写 plan.md、自己只做判断和方向(human signal)、用语音 + 多 session 并行把执行量做大。

文章主旨

这是三个月前爆款 Every Claude Code Hack I Know(913K 阅读)的续作。从独立开发者视角，讲他如何靠 Claude Code + Codex + Compound Engineering 插件，把传统"80% 写码、20% 规划"翻转成"思考全压进 plan、执行交给 agent"。22 条 hack 覆盖规划方法、语音输入、多窗口并行、YOLO 跳权限、把笔记/会议记录喂给 agent、写自己的 skill、贡献开源，以及最后一条诚实的"AI 成瘾"反思。

关键脉络

  1. 有想法的第一秒就 /ce-plan 生成 plan.md(模糊时先 /ce-brainstorm)；报错截图、issue URL、设计稿都能当起点。
  2. 做了 plan 但几乎不读——"plan 是给 agent 的镣铐"，逼它研究、定方案、写验收标准；人只看标题，问 inline 的 TLDR / eli5。
  3. /ce-plan 不止用于代码：深度非代码工作(战略文档、产品 spec)用"为 plan 做 plan"的元规划技巧，让 LLM 不偷懒。
  4. 语音驱动(Monologue / Wispr Flow / 手机 Apple 听写)——因为对面是 LLM，转写不必精确，能猜上下文。
  5. 在 cmux 里开 4–6 个 tab，每 tab 一个独立 session(写 plan / 跑 build / last30days / 修 bug)并行流水。
  6. 终端默认直接进 Claude Code 而非 shell，把"开新 session"降到一个按键的成本。
  7. 远程控制 + 给 Claude 一个邮箱(AgentMail)，手机发任务、续跑桌面上的同一个 live session。
  8. YOLO 跳权限(bypassPermissions + skipDangerousModePermissionPrompt)+ Stop 声音 hook 通知哪个 session 跑完了。
  9. Claude 做规划、Codex 做构建——两个 $200 计划当两台引擎，靠 IDE 扩展 / /ce-work --codex 不离开 Claude 就把活派给 Codex。
  10. 规划前先 /last30days 做实时社区调研，把结果喂进 /ce-plan，避免六个月前的训练数据。
  11. 把 Granola 会议原始转写(不预先总结)整段丢给 /ce-plan，让模型自己提取。
  12. "Human Signal"：跑六个 agent 时人的价值是品味、方向、react-and-redirect，不是打字。
  13. HyperFrames 把视频当 HTML 由 agent 生成，循环和写代码一样，产物是 MP4。
  14. 笔记即 agent 知识库(Bear / Obsidian / gbrain / supermemory)，挑有 CLI/API 的工具让知识复利。
  15. 远程工作：Mosh(替代慢 SSH)、tmux(飞机上断线续跑)。
  16. Proof 把 plan.md 分享给不用终端的同事评审，评论回流进 agent 循环。
  17. 写自己的 skill：凡做超过两次就做成 skill，方法是让 agent 照抄一个已有好 skill 的"形状"。
  18. 贡献开源：同一套 plan+work 循环也给别人项目提 PR，人脉 > PR 本身。
  19. 笔记本配置：M5 Max 64G 仍被六 session 拖垮，随身充电宝兜底。
  20. Printing Press：一队包装真实服务的 CLI(Tesla / Instacart / ESPN / 航司)，Agent Cookie 用真实浏览器会话解决 auth。
  21. 诚实的一段：AI 成瘾——构建是"最好玩的游戏"，但别消失在 build 里、别忽略身边人、想清楚有没有人真的要你做的东西。
  22. 这篇文章本身就是用 cmux + Monologue 语音 + Proof 评审 + last30days 喂料写出来的。

值得注意的细节

  • "Make the plan. Trust the plan. Don't read the plan." 反直觉但自洽：plan 的价值不在被人读，而在逼 agent 不偷懒。
  • 治 LLM 偷懒的最强技巧：不直接要 deliverable，而是先要它"规划如何产出 deliverable"再执行——deep 版每次都做得更好。
  • Claude Code 的 fast mode 在 $200 Max 上按 token 额外计费，所以他 Claude 关 fast、Codex 开 fast。
  • 作者坦白"在开放办公室搞不定语音"、"Obsidian 我不用但别人爱用"——愿意承认 workflow 的弱点，反而可信。
  • 数据是叙事支撑：一整年从"高中后没做过有人用的软件"到 last30days 27K stars、Printing Press 3.7K+ stars、多个项目 top contributor。

我的理解

这是一篇高密度、可执行的"实操清单"，不是方法论思辨。优点是每条都有 ### HACKS 落地动作，甚至给了能直接粘给 agent 的 prompt。缺点是带强烈的个人/营销色彩——大量自家产品(last30days / Printing Press / Agent Cookie / Monologue / HyperFrames，很多来自 Every)和 X 互推，读时要把"工具广告"和"可迁移的方法"分开。

真正可迁移的内核其实只有三条：(1) plan-first，凡事先让 agent 写计划；(2) 元规划"为 plan 做 plan"治 LLM 偷懒；(3) human-as-signal，把人从"打字的手"升级成"判断的脑"。其余多 session、语音、远程、CLI 舰队都是放大这三条的工程手段，门槛和 ROI 因人而异。

第 21 条"AI 成瘾"是全文最有价值的一段，因为它反过来质疑了前面所有 hack 的代价：你能无限放大产出，但产出未必有人要。这是少见的、作者愿意自我拆台的诚实，也让整篇从"炫技清单"升格为"有节制的经验"。

对我的参考价值

  • last30days 你已经装了(本 session 系统提示里就有)，正好印证第 10 条"规划前先调研"。可立刻试：下次写 wiki/长文前先跑一次 /last30days <主题>，把实时社区材料喂进来，而不是只靠 clippings 的静态收藏。
  • 第 17 条"写自己的 skill / 照抄已有 skill 的形状"——你这套 dread/kread/tr/wiki-* skill 体系正是这个思路的实践。反哺一下：凡你做超过两次的阅读/翻译/归档动作继续 skill 化(你已经在做，可以更激进)。
  • 第 14 条"笔记即 agent 知识库，挑有 CLI/API 的工具"——你的 LLM Wiki + Obsidian vault 就是个本地 RAG，但缺一个让 agent 跨笔记稳定检索的统一入口。可考虑给 wiki-query 固化"先扫 index 再合成"的检索层(已有雏形)，这正是作者说的"知识复利"。
  • 第 3 条"为 plan 做 plan"——可立刻动手的小实验：下次让我写复杂分析(比如 PG 某模块的对比综述)时，先让我只产出"我打算怎么读、怎么挖、怎么写"的元计划，你 review 后再执行，对比直接出文的质量差异。
  • 反面教材：全文的工具堆叠(6 session + 两个 $200 计划 + 一堆自家 CLI)对你"单机 + 面试准备"的场景是过度工程，别照搬。尤其第 8 条全程 bypassPermissions 在你会动 PG 源码、远端 mutagen 提交的环境里有风险，保持谨慎。
  • 与你已读内容的连接：这篇和 clippings 里的 Codex-maxxing、how-to-build-codex-knowledge-vault、obsidian-knowledge-vault、meta-meta-prompting 是同一簇(AI Native 工作流)。值得在 LLM Wiki 建一个"Agentic Engineering 工作流"概念页把它们串起来。
