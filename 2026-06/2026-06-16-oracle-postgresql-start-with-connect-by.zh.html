Author: Kirk Roybal
Published: June 08, 2020

现在到了我们从 Oracle 迁移到 PostgreSQL 系列的第二篇文章。这次我们将关注 START WITH/CONNECT BY 结构。

在 Oracle 中，START WITH/CONNECT BY 用于从给定的哨兵行（sentinel row）开始创建一个单链表结构。这个链表可以采用树的形式，并且没有平衡性的要求。

为了说明问题，我们先从一个查询开始，假设表中有 5 行数据。

SELECT * FROM person;
 last_name  | first_name | id | parent_id
------------+------------+----+-----------
 Dunstan    | Andrew     |  1 |    (null)
 Roybal     | Kirk       |  2 |         1
 Riggs      | Simon      |  3 |         1
 Eisentraut | Peter      |  4 |         1
 Thomas     | Shaun      |  5 |         3
(5 rows)

以下是使用 Oracle 语法对该表进行层次化查询：

select id, parent_id
from person
start with parent_id IS NULL
connect by prior id = parent_id;
 id | parent_id
----+-----------
  1 |    (null)
  4 |         1
  3 |         1
  2 |         1
  5 |         3

以下是使用 PostgreSQL 语法：

WITH RECURSIVE a AS (
SELECT id, parent_id
FROM person
WHERE parent_id IS NULL
UNION ALL
SELECT d.id, d.parent_id
FROM person d
JOIN a ON a.id = d.parent_id )
SELECT id, parent_id FROM a;
 id | parent_id
----+-----------
  1 |    (null)
  4 |         1
  3 |         1
  2 |         1
  5 |         3
(5 rows)

这个查询使用了大量 PostgreSQL 的功能，我们慢慢来拆解。

WITH RECURSIVE

这是一个"公用表表达式"（Common Table Expression，简称 CTE）。它定义了一组将在同一语句（而不仅仅是同一事务）中执行的查询。你可以有任意数量的括号表达式，以及一个最终语句。在这里我们只需要一个。==通过将该语句声明为 RECURSIVE，它将迭代执行，直到不再返回任何行为止。==

SELECT
UNION ALL
SELECT

这是递归查询的规范短语。文档中将其定义为区分起点和递归算法的方法。用 Oracle 的术语来说，可以看作是把 START WITH 子句和 CONNECT BY 子句做 UNION 拼接起来。

JOIN a ON a.id = d.parent_id

这是对 CTE 语句的自连接，为下一次迭代提供前一行数据。

为了说明其工作原理，我们给查询添加一个迭代指示器。

WITH RECURSIVE a AS (
SELECT id, parent_id, 1::integer recursion_level
FROM person
WHERE parent_id IS NULL
UNION ALL
SELECT d.id, d.parent_id, a.recursion_level +1
FROM person d
JOIN a ON a.id = d.parent_id )
SELECT * FROM a;

 id | parent_id | recursion_level
----+-----------+-----------------
  1 |    (null) |               1
  4 |         1 |               2
  3 |         1 |               2
  2 |         1 |               2
  5 |         3 |               3
(5 rows)

我们用一个值来初始化递归层级指示器。请注意，在返回的行中，第一个递归层级只出现了一次。这是因为第一个子句只执行一次。

第二个子句才是迭代魔法发生的地方。在这里，我们可以同时看到前一行的数据和当前行的数据。这使我们能够执行递归计算。

Simon Riggs 有一个非常不错的视频，介绍了如何使用这个特性进行图数据库设计。信息量很大，你应该去看一下。

你可能会注意到，这个查询可能会导致循环条件。确实如此。开发者需要在第二个查询中添加一个限制子句来防止无限递归。例如，只递归 4 层深度然后放弃。

WITH RECURSIVE a AS (
SELECT id, parent_id, 1::integer recursion_level  --<-- 在这里初始化
FROM person
WHERE parent_id IS NULL
UNION ALL
SELECT d.id, d.parent_id, a.recursion_level +1    --<-- 迭代递增
FROM person d
JOIN a ON a.id = d.parent_id
WHERE d.recursion_level <= 4  --<-- 在这里退出
) SELECT * FROM a;

列名和数据类型由第一个子句决定。请注意，示例中使用了类型转换操作符来定义递归层级。在非常深的图中，这个数据类型也可以定义为 1::bigint recursion_level。

这个图可以很方便地通过一个小的 shell 脚本和 graphviz 工具来可视化。

#!/bin/bash -
#===============================================================================
#
#          FILE: pggraph
#
#         USAGE: ./pggraph
#
#   DESCRIPTION:
#
#       OPTIONS: ---
#  REQUIREMENTS: ---
#          BUGS: ---
#         NOTES: ---
#        AUTHOR: Kirk Roybal (), kirk.roybal@2ndquadrant.com
#  ORGANIZATION:
#       CREATED: 04/21/2020 14:09
#      REVISION:  ---
#===============================================================================

set -o nounset

dbhost=localhost
dbport=5432
dbuser=$USER
dbname=$USER
ScriptVersion="1.0"
output=$(basename $0).dot

#===  FUNCTION  ================================================================
#         NAME:  usage
#  DESCRIPTION:  Display usage information.
#===============================================================================
function usage ()
{
cat <<- EOT

  Usage :  ${0##/*/} [options] [--]

  Options:
  -h|host     name Database Host Name default:localhost
  -n|name     name Database Name      default:$USER
  -o|output   file Output file        default:$output.dot
  -p|port   number TCP/IP port        default:5432
  -u|user     name User name          default:$USER
  -v|version    Display script version

EOT
}

#-----------------------------------------------------------------------
#  Handle command line arguments
#-----------------------------------------------------------------------

while getopts ":dh:n:o:p:u:v" opt
do
  case $opt in
    d|debug    )  set -x ;;
    h|host     )  dbhost="$OPTARG" ;;
    n|name     )  dbname="$OPTARG" ;;
    o|output   )  output="$OPTARG" ;;
    p|port     )  dbport=$OPTARG ;;
    u|user     )  dbuser=$OPTARG ;;
    v|version  )  echo "$0 -- Version $ScriptVersion"; exit 0 ;;
    \? )  echo -e "\n  Option does not exist : $OPTARG\n"
          usage; exit 1 ;;
  esac
done
shift $(($OPTIND-1))

tee "$output" <<EOF
digraph g {
    node [shape=rectangle]
    rankdir=LR
EOF

psql -h $dbhost -U $dbuser -d $dbname -p $dbport -qtAf cte.sql |
    sed -e 's/^/node/' -e 's/.*(null)|/node/' -e 's/^/\t/' -e 's/|[[:digit:]]*$//' |
    sed -e 's/|/ -> node/' | tee -a "$output"

tee -a "$output" <<EOF
}
EOF

dot -Tpng "$output" > "${output/dot/png}"
open "${output/dot/png}"

这个脚本需要一个名为 cte.sql 的 SQL 文件：

WITH RECURSIVE a AS (
SELECT id, parent_id, 1::integer recursion_level
FROM person
WHERE parent_id IS NULL
UNION ALL
SELECT d.id, d.parent_id, a.recursion_level +1
FROM person d
JOIN a ON a.id = d.parent_id )
SELECT parent_id, id, recursion_level FROM a;

然后像这样调用：

chmod +x pggraph
./pggraph

你会看到生成的图。

添加一个新节点：

INSERT INTO person (id, parent_id) VALUES (6,2);

再次运行该工具，立即看到有向图的变化。
